새 디지몬 그림은 큰 시트(4x3)를 받아 96x96 PNG 12장(`이름_01~12`)으로 잘라 `resource/디지몬/<이름>/`에 넣는다. 시트 원본과 톤다운 전 파일은 `원본그림/<이름>/`, 자르기·톤다운·목업 스크립트는 `원본그림/_도구/`.

누끼 zip 처리 (2026-11-26~): 사용자가 누끼를 다른 곳에 맡겨 zip(원본 해상도 PNG 12장)을 프로젝트 루트에 두면, 확인 후 `python 원본그림/_도구/import_zip.py <zip> <폴더이름> [톤 0/0.5/1/2] [wide]`로 저장한다. 누끼는 사용자가 GPT 쪽에서 따 온다. 내가 시트에서 직접 누끼를 따는 것은 사용자가 거절함(2026-11-26) — 제안하지 말고 zip을 기다린다. 특정 칸만 다른 시트 것으로 바꿀 때(파피몬 04·11번 선례)는 두 zip을 받아 12장을 합친 뒤 저장한다. 이 스크립트가 96칸 변환·톤다운·zip을 `원본그림/<이름>/누끼_원본.zip`으로 옮기기·목업 갱신까지 한다. 루트에 zip을 남기지 않는 게 사용자 요청("집파일 앞으로 자동 정리"). 흰 몸 디지몬은 어두운 배경에 올려 흰 부분이 안 지워졌는지 먼저 확인.

크기 결정 (2026-11-25):
- 게임은 단계별 목표 키(`pet.pyw` STAGE_FIT)보다 작은 그림만 키운다.
- 콩알몬(390)과 메탈콩알몬은 "작은데 강한" 콘셉트라 확대하지 않는다. 메탈콩알몬은 아직 게임 종 번호가 없어서, 연결할 때 `pet.pyw` KEEP_SIZE에 추가해야 한다(목업 스크립트에는 KEEP_NEW로 반영됨).

- 파피몬은 뿔 때문에 키 기준 자동 맞춤이 안 맞아서, 뿔을 뺀 머리 높이를 아구몬에 맞춘 배율 1.37을 따로 씀(목업 SIZE_NEW). 게임 연결 때 pet.pyw에도 종별 배율 덮어쓰기가 필요. 뿔 긴 디지몬은 이 방식으로 맞춘다(사용자 결정 2026-11-26). 가루몬도 머리 갈기 때문에 1.45 (자동 1.28 대신).
- 옆으로 넓은 디지몬(블리츠그레이몬 등)은 import_zip.py 끝에 `wide`를 붙여 키만 96에 맞추고 가로를 넓힌 캔버스로 저장(사용자 결정 2026-11-26: 폭 때문에 작게 만들지 않음). 게임 연결 때 가로 96 넘는 그림이 펫 창(W=77)에서 잘리지 않는지 확인 필요.

저장 후 할 일:
- 목업: `원본그림/_도구/stage_mockup.py`의 NEW에 `'폴더': ('이름', g.단계)` 추가 (import_zip이 목업을 다시 만듦). 기존 48칸 종을 새로 그린 경우 이름 뒤에 "(새)".
- 진화표: `원본그림/_도구/evo_chart.py` HAVE에 `'이름': '폴더'` 추가 후 실행 → `진화표_작업/` 갱신. 그다음 `evolution-atlas/`에서 `python build.py`. 종 수가 바뀌면 build.py의 assert(총 종 수, 단계별 수)와 index.template.html 문구도 같이 고친다.
- GPT가 배포한 사이트(chatgpt.site)는 그림만 GitHub에서 자동으로 읽고, 종·진화 경로는 GPT가 다시 배포해야 반영된다.
