프롬프트 작성 순서: 1) 나와 GPT가 각각 분석 2) 사용자가 GPT 의견을 나에게 공유 3) 내가 종합해 최종 프롬프트 작성. GPT 의견은 무조건 받아들이지 않고, 공식 디자인과 96칸 가독성 기준으로 골라 반영한다. 반영하지 않은 항목은 이유를 짧게 적는다.

프레임 순서의 02 걷기 문구 (2026-11-27): "01 자세 그대로, 발 위치 고정, 무릎을 굽혀 몸 전체가 3~5픽셀 내려가고 상체가 앞으로 기울며 팔이 조금 흔들림. 발 들기·발바닥 보이기·크게 내딛기·팔 크게 흔들기 없음". "한 발을 크게 내딛고"는 더 이상 쓰지 않는다. [[digipet-sprite-pipeline]]

최종 프롬프트 형식 (사용자 지시 2026-11-26): 맨 앞 [기준]에 첨부 이미지를 번호로 적고, 각 이미지를 무엇에 쓰는지(디자인 기준 / 구조 확인용 / 도트 화풍·자세 기준)와 섞으면 안 되는 요소를 명시한다. 화풍 기준으로는 같은 계열의 통과된 시트(예: 블리츠그레이몬 → 워그레이몬 시트)를 쓰고, 그 시트 고유 디자인 요소는 "섞지 않는다"로 막는다. 첨부할 웹 이미지는 코드 블록 텍스트가 아니라 클릭되는 마크다운 링크로 주고, 내장 브라우저 탭에 띄워 둔다(사용자 요청).

수정 요청 형식 (사용자 방식 2026-11-26): 결과 시트가 틀리면 공식 이미지 1~2장 + 이번 결과 시트를 첨부하고, [첨부]에서 각 이미지의 용도(디자인 기준 / 구조 확인 / 수정 대상)를 적는다. 결과 시트만 첨부하거나 결과 시트를 빼라고 하지 않는다. 회사 예시(크레스가루몬 칼날 수정) 형식: 첫 줄 "첨부 1(결과 시트)을 유지하고 ~만 고쳐서 다시 그려줘" → 첨부 1 = 결과 시트, 첨부 2(·3) = 공식 이미지 → [수정할 것 – 적용 칸] (지금 상태 한 줄 → 바꿀 모양을 선·방향·휘어짐 단위로 구체적으로, 틀린 모양은 "~없음"으로 막기, 크기 기준) → [그대로 유지할 것] (자세·크기·발바닥 높이·부위별 디자인·색·화풍·구성 나열). 이어서 [디자인 – 첨부 1과 같게] [체형] [화풍] [분위기] [구성] [프레임 순서] 순서.

**Why:** 사용자가 "GPT의 제안이니 무조건 수용할 필요 없음"이라고 하며 이 순서를 정함 (2026-11-26).

**How to apply:** 사용자가 표나 제안을 붙여 넣으면 GPT 분석으로 보고 비교 검토한다. 관련: [[official-design-faithful]], [[digipet-sprite-pipeline]]
